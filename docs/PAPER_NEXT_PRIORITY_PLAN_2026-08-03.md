## 우선순위와 완료 조건

### 1. 오늘 PAPER 세션 완주

장 마감 후 자동 EOD 경로에서 다음을 모두 확인한다.

- 오늘 날짜의 EOD 상태가 `PAPER` / `READY` / return code 0
- 일일 리포트가 `FINAL` / `READY`
- 데이터 신선도·위험점검·주문 대사·운영 무결성 통과
- 미종결 주문 0건
- 원장, 주문, 체결, 보유수량의 endpoint 대사 일치

하나라도 실패하면 해당 날짜를 READY로 승격하지 않고 원인 증거를 남긴다.

### 2. 실행 표본 30건 기준 달성

현재 남은 자연 관측량은 BUY 10건, SELL 13건이다. 양쪽이 각각 30건에 도달할 때까지 실행 스트레스 결과는 `PROVISIONAL_SMALL_SAMPLE`로 유지한다.

표본 기준 달성 뒤에도 다음을 별도로 검토한다.

- 체결률과 Wilson 95% 하한
- 이상 체결·거부·부분 체결의 비율
- `C_CAP10` / `C_CAP08`의 위험 기준 통과 여부
- 현재 전략 대비 수익·MDD·회전율 개선 여부

관측 결과가 기준을 통과해도 production 규칙은 수동 승인 전까지 변경하지 않는다.

### 3. shadow 및 portfolio-cap 관측 누적

- shadow: 고유 세션 10회 이상, 각 세션의 FINAL/READY 리포트와 연결
- `C_CAP10` / `C_CAP08`: 관측 전용으로 10회 이상 누적
- shadow와 challenger 모두 주문 권한은 계속 `DENIED_BY_DESIGN`

### 4. PAPER 60세션 및 FINAL/READY 60개 누적

누락·무효 과거 날짜는 원본 로그를 다시 쓰지 않는다. 복구 가능한 장애와 복구할 수 없는 과거 데이터 공백을 별도 증거로 보존하고, 새 세션부터 같은 검증을 자동 적용한다.

### 5. 최종 readiness 재감사

위 조건이 모두 충족된 뒤에만 전체 readiness를 재감사한다. `full_system_complete=true`가 되기 전에는 REAL 실행을 승인하지 않는다. 전략 후보나 위험 한도 변경은 별도 비교 보고서와 수동 승인을 요구한다.

## 운영 원칙

1. PAPER 런타임이 안전해도 전체 시스템 완료와 동일하게 취급하지 않는다.
2. 데이터 공백, broker 오류, 주문 억제는 원인별로 분류하되 readiness gate를 임의로 완화하지 않는다.
3. 장중 주문 기록은 operational log, trade history, PostgreSQL orders/executions를 서로 대조한다.
4. 보고서 생성 실패 시 실패 상태를 보존하고 다음 재시도에서만 복구를 시도한다.
