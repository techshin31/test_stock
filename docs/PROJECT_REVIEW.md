# 프로젝트 검토 및 개선 결과

검토일: 2026-10-01. DB 설정·마이그레이션, 대시보드 API·데이터 갱신,
주문 계획·제출·체결 동기화, 성과 지표와 개발 검증 자동화를 검토하고 개선했다.
외부 API·실주문 검증이나 전체 코드 보안 감사는 포함하지 않는다.

## 완료한 개선

| 항목 | 변경과 결과 |
| --- | --- |
| DB 접속 | `storage/postgres/migrate.py`에서 psycopg `make_conninfo`를 사용해 특수문자 비밀번호를 올바르게 처리한다. 실제 임시 DB 역할로 접속도 검증했다. |
| 종목명 조회 | 빈 종목명 조회 결과도 캐시한다. 미조회 상태와 빈 결과를 구분하고, 캐시 만료 후 새 종목명을 읽는다. |
| CAGR | 최초·최종 자산값 사이의 수익률 구간 수로 기간을 계산한다. 253개 관측값/252개 구간의 10% 수익률은 연환산 10%가 된다. 중간 결측 행도 경과 기간에 포함하며 양 끝 결측 행은 제외한다. 성과 보고서·기여도 집계가 원본 자산 곡선의 기간을 유지하도록 변경했다. |
| 데이터 갱신 | 대시보드의 각 데이터 요청에 마지막 성공 응답 시각·갱신 오류를 표시한다. 실패 시 이전 응답과 시각을 유지하고, 복구 시 오류를 해제한다. 자동 갱신·수동 갱신·15초 시간 초과를 처리하며, 취소되거나 이전 요청인 응답이 새 상태를 덮어쓰지 않도록 한다. |
| 초기 상태 | `/api/overview`는 상태 파일이 없으면 `dashboard=null`과 `NOT_STARTED` 또는 `DATA_PENDING`을 반환한다. 초기 계좌·성과 수치를 만들지 않는다. JSON 손상 등의 오류는 정상 초기 상태로 숨기지 않는다. 화면의 고정 계좌 표기도 실제 상태값 또는 미확인 안내로 교체했다. |
| CI | `.github/workflows/ci.yml`에 Python 테스트, 대시보드 빌드·린트·Chromium 검사, PostgreSQL 16 연동 검사를 별도 작업으로 구성했다. PR과 `main` 푸시에 실행하며 읽기 권한만 사용한다. |
| API 분리 | `api/reports.py`에 JSON 파싱·보고서 요약·최신성 정책, `api/market_data.py`에 관측 시계열 계산, `api/database.py`에 DB 연결 설정을 분리했다. 기존 HTTP 라우트는 `api/main.py`에 유지한다. |
| 트레이더 분리 | `core/execution/order_planning.py`, `order_execution.py`, `order_reconciliation.py`에 각각 계획·주문 제출·체결 및 계좌 동기화 책임을 분리했다. `LiveTrader`는 실행 흐름을 조율한다. 16개 이동 메서드의 로직이 시계 주입 경계 외에는 동일한 것을 확인하고 기존 안전 테스트를 실행했다. |

## 검증

- Python 기존 테스트와 회귀 테스트: **404개 통과** (`pytest tests -q`).
- 실제 PostgreSQL 연동: **2개 통과**. 고유 임시 DB에서 초기 스키마와 시드,
  마이그레이션 08/09·재실행, API DB 건강 검사, 특수문자 비밀번호 접속을 검증했다.
- 실제 Chromium 브라우저: **7개 통과**. 최초 화면, 갱신 실패·복구, 서버 오류,
  최초 요청 실패, 시간 초과, 자동 갱신, 운영 데이터 준비 상태를 검증했다.
  시장 서비스는 모의 HTTP 응답으로 검사하므로 실제 시장 데이터 정확성을 입증하지는 않는다.
- `npm ci`, 대시보드 빌드·린트 통과.
- 재시작한 API와 로컬 PostgreSQL에서 건강 검사 및 초기 `/api/overview` HTTP 200 확인.
  대시보드 프록시를 통한 DB 건강 검사도 HTTP 200 확인.
- CI YAML과 작업 구성을 로컬에서 검사했다. GitHub Actions 원격 실행은 아직 수행하지 않았다.

명령과 요구 사항은 저장소 README와 대시보드 README에 기록했다.

## 계산 규칙과 운영상 제한

CAGR 입력은 거래일별 행을 갖는 자산 곡선이어야 한다. 중간 결측 행은 계산 기간에
포함하지만, 애초에 인덱스에 없는 거래일은 추정하지 않는다. 거래일 그리드가 누락된
입력은 호출자가 먼저 맞춰야 한다. 수정된 기간 규칙에 따라 과거 백테스트의
CAGR·Calmar가 달라질 수 있으며, 저장된 과거 보고서를 임의로 재작성하지 않았다.

응답 확인 시각은 시세 관측 시각과 다르다. 대시보드는 마지막 성공 요청과 갱신
오류를 보여주며, 시장 데이터의 실제 관측일과 출처는 각 화면에서 확인한다.

매매 전략과 주문 안전 조건은 변경하지 않았다. PAPER/REAL 주문이나 스케줄러를
시작하지 않았고, 외부 수집·증권 API를 검증하지 않았다. 개발용 DB는 현재 환경의
PostgreSQL 16.2를 사용했으며 CI는 공식 PostgreSQL 16 이미지를 사용하도록 구성했다.
DB 연결 실패의 종목명 캐시 재시도 정책과 나머지 대형 모듈 분리는 이번 범위 밖이다.
